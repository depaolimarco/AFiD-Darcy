# Outputs

The code either outputs files with extension `.out` that are in human-readable text format, or in HDF5 files with extension `.h5` that contain data in hierarchical format. Reading in both types of output into post-processing scripts (e.g. written in MATLAB or python) should be trivial. 

Depending on the user choices made in the inputs provided to the code, different set of outputs may be generated by the code. The following is an explanation of the full set of outputs that can be generated. All the output files are conveniently stored in a directory named `Results`.

## Grid metrics and coordinates

The files that deal with grid metrics are `Results/axicor.out`,`Results/cordin_info.h5`, `Results/diffc.out`, `Results/diffc_surf.out`, and `Results/fact3.out`. The most important file containing the Cartesian grid-coordinates is `Results/cordin_info.h5` with the structure as shown below. 

```
Results/cordin_info.h5
╠═> xc ═> (NX)  <float64>
╠═> xm ═> (NXM) <float64>
╠═> yc ═> (NY)  <float64>
╠═> ym ═> (NYM) <float64>
╠═> zc ═> (NZ)  <float64>
╚═> zm ═> (NZM) <float64>
```
Here, the array sizes are indicated in the parenthesis and the data type is indicated in the angle brackets. The file `Results/axicor.out` also contains the coordinates of the non-uniform grid in the wall-normal direction with some coefficients for discrete differentiation operators. Coefficients for additional discretized operators can be found in the other files, but these are more useful for debugging purposes.

## Global quantities

Global quantities are written out whenever the number of time steps is divisible by the input parameter `NOUT`. 

### Volume averaged quantities

Volume averaged velocities are noted against simulation time in `Results/vol_avg.out`, and the root mean squared values non-dimensionalized as Reynolds numbers are stored in `Results/rms_vel.out`. The volume averaged scalar flux non-dimensionalized as Nusselt number is stored in `Results/nu_vol.out`. 

### Flux quantities

Scalar fluxes at the top (`NuT(dT/dy)`) and bottom (`NuB(dT/dy)`) walls, non-dimensionalized as Nusselt numbers, are noted against time in `Results/nu_darcy.out`. This file also contains the Nusselt number computed from the global average of scalar dissipation rate (`chi`), average of scalar (`c1`), discrete derivative of scalar in time (`dc1dt`), average of the square of the scalar (`c2`), and the discrete derivative of the square of the scalar in time (`dc2dt`). 

## Profiles

All profiles are obtained by averaging the 3D flow-fields along the periodic wall-parallel directions. These can be plotted against the coordinate arrays `xc` or `xm` depending on whether the quantity being plotted resides at the cell-centre or at the top and bottom faces of the grid cells. However, the profiles are always arrays of size `NXM`, because it is assumed that the vertical velocity at the top wall, and any subsequent moments are zero. Therefore, it is redundant to store the extra data at the top wall.

## 3D Flow-field snapshots

When the simulation time exceeds the input value set by `STARTSNAP`, the 3D flow-field snapshots are stored at intervals set by `SAVESNAP`. These flow-fields can also be used as "checkpoints" from which the simulation can be restarted in the event of an unforeseen termination. Additionally, these flow-fields can be used for 3D visualizations using tools like Paraview. Each flow-field is stored separately. For example, the initial velocity is stored in the location

```
Results/Vx/continua_vx00000000.h5
╚═> var ═> (NZM, NYM, NX)  <float64>

Results/Vy/continua_vy00000000.h5
╚═> var ═> (NZM, NYM, NX)  <float64>

Results/Vz/continua_vz00000000.h5
╚═> var ═> (NZM, NYM, NX)  <float64>

Results/Temp/continua_temp00000000.h5
╚═> var ═> (NZM, NYM, NX)  <float64>
```

For `vy`, `vz`, and `temp`, the useful data is only contained up to `(:,:,:NXM)` whereas last slice at `(:,:,NX)` is redundant and is usually zero. 

## Continua checkpoint
Upon the successful completion of the simulation, checkpoint files will be stored to continue the simulation in the future if needed. These include `continua_master.h5`, `continua_vx.h5`, `continua_vy.h5`, `continua_vz.h5`, `continua_temp.h5`. These are not intended to be used for post-processing although, they may be, if so desired.
